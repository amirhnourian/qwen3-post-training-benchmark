# Methods and interpretation

## Scope and provenance

The measured study used Qwen3-8B on one private fixed agent task with a
deterministic verifier. This public repository contains a later generic
refactor, an unrelated synthetic arithmetic demo and sanitized aggregate
measurements. It does not release the original task, expected outputs,
trajectories, supervised targets or adapters. Public tests validate this
refactor; they are not evidence that its current source was the exact measured
implementation.

Coding assistants supported implementation, review and collection-prompt
design. The accepted supervised target tokens were generated by Qwen3-8B.
Assistance during target generation is disclosed separately from that authorship.

## Evaluation and uncertainty

| Policy | Strict passes / attempts | 95% Wilson interval |
| --- | ---: | ---: |
| Unadapted Qwen3-8B | 0/100 | 0.00–3.70% |
| Qwen3-8B + RSFT adapter | 100/100 | 96.30–100.00% |
| Qwen3-8B + RSFT/GRPO adapter | 100/100 | 96.30–100.00% |

An experimental unit is one full fresh rollout. Strict success requires the
complete verifier definition to pass. Fractional reward is reported separately;
partial credit is not strict success. Invalid actions, wrong answers and
budget exhaustion remain agent outcomes. Infrastructure errors are identified
explicitly rather than silently replacing poor samples.

Primary before/after cohorts used the same task observation, tools, tokenizer
template, quantization and inference budgets. Evaluation disabled explicit
thinking and used temperature 0.7, top-p 0.8 and top-k 20. Limits were 16,384
context tokens, 4,096 new tokens per turn, 16,384 total new tokens and twelve
turns. Each stage used a distinct 100-seed cohort. Final adapter states were
chosen by declared training budgets, not by selecting the best final-evaluation
checkpoint.

Each phase uses a 95% Wilson score interval. Differences use an independent-
sample Newcombe interval based on Wilson bounds. RSFT minus baseline is
**+100.00 percentage points**; GRPO minus RSFT is **0.00 points**, with an
approximately **−3.70 to +3.70 point** interval for the latter. Exact-test
statistics, when present in the aggregates, are descriptive for this fixed
comparison and do not correct for every adaptive development decision.

See [NIST](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)
and [the Newcombe-method reference](https://www.statsmodels.org/stable/generated/statsmodels.stats.proportion.confint_proportions_2indep.html).

## Environment adjustments

Input-path inconsistencies and missing execution scaffolding were repaired
before the primary baseline. The model received the unchanged source inputs
in its initial observation and could use bounded tools. The same interface
was retained for all three evaluation stages. Setup repair was therefore not
counted as a weight-training gain.

Disagreements between the private source's literal behavior and its intended
grading interpretation were disclosed in the original study. The supplied
scoring definition was preserved rather than revised to make results easier
to obtain. Task-specific details are not reproduced in this public release.

## Own-success RSFT

Independent training collection did not yield a usable success. Generic
feedback-assisted correction also did not supply accepted targets. A
separately declared source-guided search then emphasized relevant information
already present in the task without supplying computed expected outputs.
This is **task-specific collection assistance**, stronger than independent
rejection sampling under the baseline prompt.

Accepted targets were exact suffixes of the same unadapted model's verified
successful generations. Strict filtering, completed-submission requirements,
length checks and exact-action deduplication retained **one distinct
trajectory**, giving **two assistant-turn examples** and **132 supervised
tokens per dataset pass**. Repeated examples and multiple assistant turns
are not additional independent demonstrations.

The student context was reconstructed using the frozen non-thinking interface.
Collection guidance and source reasoning were excluded. This was an explicit
action-only self-distillation transformation, not an unchanged full-trajectory
replay. Removing help from the student context does not remove its influence
on the generated demonstration. The public builder exposes this transformation
and records token ranges, identities and assistance disclosure.

Prompt, history and tool-response labels are `-100`; only selected assistant
tokens contribute to the causal token loss. Whole oversized trajectories are
rejected rather than silently truncated. Vocabulary projection is restricted
to the causal positions predicting supervised tokens while the transformer
retains the full context. Tests compare this selected-position loss and its
gradients with a dense calculation.

Related work: [ReST](https://arxiv.org/abs/2308.08998). It is background rather
than a claim to reproduce that paper's complete method.

## QLoRA and supervised optimization

The frozen base used NF4 four-bit weights with double quantization and BF16
computation. LoRA rank was **16**, alpha **32**, dropout **0**, and learning
rate **1e-4**. Adapter updates covered attention and feed-forward projections.
The maximum training length was **8,192** tokens, microbatch size **1**, and
configured gradient accumulation **4**.

The fixed stop condition was **40 cumulative optimizer updates**. Training
resumed from checkpoint **26** to complete update **40** under the same dataset
and settings, restoring optimizer, scheduler and RNG state. This is one
continued run. Configured accumulation should not be mistaken for measured
microbatches per update, especially with a two-example dataset and epoch-boundary
flushes.

The model and adapter workload ran on an **RTX 5090 with 32 GB VRAM**; the host
had an **AMD Ryzen 9 9950X3D** and **60 GiB usable RAM**. This establishes
feasibility for the chosen quantized adapter workload, not full-parameter
training under arbitrary context lengths.

Background: [LoRA](https://arxiv.org/abs/2106.09685),
[QLoRA](https://arxiv.org/abs/2305.14314), and
[PEFT quantization](https://huggingface.co/docs/peft/developer_guides/quantization).

## Online GRPO continuation

The second training stage continued the completed RSFT adapter. It used a
custom online multi-turn GRPO implementation, not the TRL trainer.

| Setting | Declared value |
| --- | --- |
| Fresh rollout groups | 12 |
| Rollouts per group | 4 |
| Inner clipped updates | 2 per nonconstant-reward group |
| Actual completed updates | 16 |
| Equal-reward groups | 4; both updates skipped |
| Learning rate | 5e-6 |
| Clip epsilon | 0.2 |
| KL coefficient | 0 |
| Exploration temperature | 2.0 |
| Sampling support | Full support: top-p 1, top-k 0 |
| Loss normalization | Mean model-token objective per trajectory, then group mean |

All sampled model actions, including unsuccessful actions and EOS, were eligible
for the policy objective. Tool observations were context, not model-generated
action targets. The original verifier supplied terminal fractional rewards.
Advantages centered each reward by its group mean and divided by the population
standard deviation plus a small stabilizer. Groups with zero variance remained
in the reward curve and received no optimizer step.

Old log probabilities were fixed for both inner updates. Current and old
likelihoods used the same full-support temperature policy. The clipped
surrogate used token-level current/old ratios; clipping limits the objective's
incentive for large changes and is not a hard ratio bound. No reference-policy
KL term was used. The normalization follows the original trajectory-mean form
rather than evolving library defaults.

The four exploratory pilot episodes were excluded from training and final
evaluation. Exploration limits differed from the frozen benchmark: four turns,
1,024 new tokens per turn and 2,048 total new tokens. Training-group rewards
therefore describe that exploration policy. They are not a held-out benchmark
curve. A final separate 100-attempt cohort used the original evaluation settings.

Read [DeepSeekMath §4.1](https://arxiv.org/html/2402.03300v3#S4.SS1) and
[TRL's method guide](https://huggingface.co/docs/trl/grpo_trainer) for the
objective and common variants.

## Limits

The same underlying task and answers recur during training and evaluation.
Fresh seeds test stochastic reliability, not transfer to unseen tasks.
Task-specific memorization is plausible with one short accepted trajectory.
There is one trained adapter sequence, so attempt-level intervals do not
estimate variation between independent training runs.

The baseline policy was a declared bounded interface, not a claim about the
best achievable untrained policy under every prompt and reasoning budget.
Collection used stronger and assisted policies; those changes are explicit.
Both final trained cohorts achieved 100/100, leaving no observed pass-rate
headroom for GRPO. The public aggregate files cannot independently establish
target authorship or replay private scoring; the original private evidence
provided those checks. Public verification checks arithmetic and internal
consistency of the released aggregates.
